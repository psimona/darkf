## Pass 2 (2026-10-14) — /council review
Convened: Devil's Advocate, Optimist, Realist, Runtime/Engine Internals,
Build/Tooling Engineer. Record: docs/council/2026-10-14-1429-workflow-validation.md

Applied all 7 fixes identified:
1. (Convergent, blocking) EXIT was wrongly exempted as a valid composite
   `initial` — `enter()` has no EXIT case, so it would still crash at
   runtime despite passing eager validation. Fixed: EXIT is now valid only
   for leaf `on`/`next`, never for any `initial` (composite or top-level).
2. (Convergent) Cycle dedup: per-composite-start walking re-reported the
   same cycle once per feeder composite. Fixed: canonicalize + dedupe.
3. Cycle walk must start from every composite in the registry, not just
   `workflow.initial`'s own chain. Fixed: stated explicitly.
4. unresolved-target vs. initial-cycle precedence during the walk. Fixed:
   an unresolved id mid-chain stops the walk as unresolved-target, not a
   cycle continuation.
5. `crashed()`'s state/scopePath convention for `invalid-workflow` was
   unstated. Fixed: pinned to `(reason, 0, opts.workflow.initial, [])`,
   mirroring `DuplicateStateIdError`'s existing convention.
6. (Convergent) `from: "<root>"` string sentinel could collide with a real
   state named `<root>`. Fixed: `from: string | null`, `null` = top-level.
7. (Convergent, low severity) run()/doctorCmd registry-duplication noted
   as a flagged future-extraction trigger, not fixed now.

No open issues. Spec is ready.
